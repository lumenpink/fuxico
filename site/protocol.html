PROTOCOL SPECIFICATIONS

Fuxico implements 5 core communication protocols: The Null Pointer (0x0.st), rustypaste, Markdown Zine Docs, Multi-File Gists, and Git HTTP Smart Protocol.

🌐 cURL & Git Native Compatibility 🔑 X-Token Management Header 📝 Markdown, Gists & Bare Repositories

0️⃣ 1. The Null Pointer Protocol (0x0.st)

Send standard multipart forms via POST /:

Field / Parameter Type Description
file File Multipart File content payload to upload.
url String URL Instructs the server to download and store content from a remote URL.
shorten String URL Shortens the provided target URL and generates a redirect link.
secret Flag / Empty Generates an unguessable 16-character high-entropy secret slug.
expires Integer / String Retention duration in hours (e.g. 24) or ms epoch timestamp.
oneshot Flag / Boolean If set, file evaporates immediately after its first download.

cURL Examples

curl — 0x0.st examples 
# Upload with 24 hours expiration:
curl -F 'file=@photo.png' -F 'expires=24' https://fuxico.2lp.in/

# Shorten a URL:
curl -F 'shorten=https://codeberg.org/lumenpink/fuxico' https://fuxico.2lp.in/

# Manage / Delete using X-Token:
curl -F 'token=<X-Token>' -F 'delete=' https://fuxico.2lp.in/abcde.png

🦀 2. Rustypaste Protocol

Send files using HTTP headers for configuration:

Header / Endpoint Format Description
expire: <duration> Header Duration string: 10m, 2h, 7d, etc.
oneshot: true Header Enables single-download self-destruction.
filename: <name> Header Custom filename alias override.
DELETE /<slug> HTTP Method Deletes an upload using Authorization: Bearer <token>.
GET /list JSON Endpoint Returns active uploads list in structured JSON format.

cURL Examples

curl — rustypaste examples 
# Upload with 10 minutes lifetime header:
curl -F 'file=@secret.txt' -H 'expire: 10m' https://fuxico.2lp.in/

# Delete via DELETE method:
curl -X DELETE -H 'Authorization: Bearer <token>' https://fuxico.2lp.in/abcde.png

# List active uploads:
curl -H 'Authorization: Bearer <token>' https://fuxico.2lp.in/list

📎 3. Friendly Subpath Aliasing

Need to share a file so it saves with a recognizable human name rather than a random slug? Fuxico natively supports subpath aliasing:

Subpath URL Structure 
https://fuxico.2lp.in/<slug>.<ext>/<friendly_filename>

Example: https://fuxico.2lp.in/8x9yt.png/avatar-lumen-2026.png streams the exact same payload while setting Content-Disposition: inline; filename="avatar-lumen-2026.png".

📝 4. Markdown Zine Publishing Protocol

Upload standard Markdown documents to publish beautiful standalone web readers with syntax highlighting, Obsidian callouts, and dual-skin toggle:

Field / Query Format Description
POST /api/doc or POST / (doc=true) Multipart Uploads Markdown payload and triggers atomic HTML rendering.
GET /<slug> Content-Negotiated Web browsers receive rendered standalone HTML reader; curl receives pure raw Markdown.
GET /<slug>?raw=1 Raw Text Explicitly forces raw untouched Markdown source delivery.
POST /<slug>/assets Multipart Uploads static images or attachments scoped to /<slug>/assets/<filename>.

cURL Example

curl — markdown docs example 
# Publish Markdown document as standalone Zine doc:
curl -F 'file=@article.md' -F 'doc=true' https://fuxico.2lp.in/

📦 5. Multi-File Gist Protocol

Send multi-file code pastings as JSON payloads via POST /api/gist. Fuxico bakes a tabbed viewer and provides instant raw and zip endpoints:

cURL — publish multi-file gist 
curl -X POST https://fuxico.2lp.in/api/gist \
  -H "Content-Type: application/json" \
  -d '{
    "files": [
      { "name": "main.rs", "content": "fn main() { println!(\"olá!\"); }" },
      { "name": "Cargo.toml", "content": "[package]\nname = \"demo\"\nversion = \"0.1.0\"" }
    ],
    "expires": "7d",
    "oneshot": false
  }'

Endpoints Available:
• Web Viewer: https://fuxico.2lp.in/<slug> (Tabbed interactive code view)
• Raw File: https://fuxico.2lp.in/<slug>/raw/<filename> (Single file raw content)
• Zip Archive: https://fuxico.2lp.in/<slug>/zip (Bundled ZIP of all files in gist)

🌱 6. Git HTTP Smart Protocol

Host ephemeral or long-lived bare Git repositories over standard HTTP smart protocol without SSH daemons:

bash — Git HTTP lifecycle 
# 1. Initialize bare repository via CLI:
fux git init my-project

# 2. Add remote to existing local git repo:
git remote add fuxico https://<TOKEN>@fuxico.2lp.in/<slug>.git

# 3. Push commits:
git push fuxico main

# 4. Clone from any machine:
git clone https://fuxico.2lp.in/<slug>.git
